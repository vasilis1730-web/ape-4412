# ΑΠΕ — Ανακεφαλαιωτικοί Πίνακες Εργασιών

Σύνταξη και έλεγχος Ανακεφαλαιωτικών Πινάκων Εργασιών κατά τα άρθρα **153**
(αναθεώρηση τιμών) και **156** (τροποποίηση σύμβασης) του **Ν. 4412/2016**.

Η εφαρμογή διαβάζει τον προϋπολογισμό μελέτης και το έντυπο οικονομικής
προσφοράς του Ε.Σ.Η.ΔΗ.Σ. απευθείας από PDF, υπολογίζει τα όρια του νόμου,
και συντάσσει τον Πίνακα, την αιτιολογική έκθεση, την εισήγηση, το αίτημα
προς το Τεχνικό Συμβούλιο και το Π.Κ.Τ.Μ.Ν.Ε.

Περιλαμβάνει και την αντίστροφη λειτουργία: **έλεγχο Πίνακα που συνέταξε
τρίτος**, με ανεξάρτητο επανυπολογισμό κάθε γραμμής και κάθε ορίου.

## Αρχεία

| | |
|---|---|
| `index.html` | Ολόκληρη η εφαρμογή. Ένα αρχείο, **μηδέν εξαρτήσεις**. |
| `config.js` | Διεύθυνση και δημόσιο κλειδί της βάσης. |
| `supabase/migrations/` | Σχήμα βάσης και πολιτικές ασφαλείας. |
| `supabase/functions/` | Ανάγνωση σαρωμένων εγγράφων (Edge Function). |

Ο αναγνώστης PDF, ο writer του Excel και ο συγχρονισμός με τη βάση είναι
γραμμένα από την αρχή μέσα στο `index.html`. Δεν φορτώνεται καμία εξωτερική
βιβλιοθήκη, δεν υπάρχει build step. Ανοίγει και με διπλό κλικ.

## Εγκατάσταση

### 1. Βάση δεδομένων

**Έχει ήδη στηθεί.** Το project `ape-4412` είναι ενεργό και οι τρεις
migrations έχουν εφαρμοστεί:

```
20260823120000_core_schema.sql            πίνακες, triggers, πολιτικές RLS
20260823121000_documents_storage.sql      bucket εγγράφων και πολιτικές
20260823122000_harden_trigger_functions.sql  ανάκληση EXECUTE από τις trigger functions
```

Για νέο περιβάλλον: εφαρμόστε τις με τη σειρά από το SQL Editor ή με
`supabase db push`.

### 2. Ρύθμιση σύνδεσης

**Έχει ήδη συμπληρωθεί** στο `config.js`. Για άλλο περιβάλλον, τα στοιχεία
βρίσκονται στο **Project Settings → API**:

```js
window.APE_SUPABASE_URL  = 'https://xxxxx.supabase.co';
window.APE_SUPABASE_ANON = 'eyJhbGci...';
```

Το `anon` κλειδί **δεν είναι μυστικό** — προορίζεται για τον browser και η
πρόσβαση ελέγχεται αποκλειστικά από τις πολιτικές RLS. Το `service_role`
κλειδί δεν μπαίνει ποτέ σε αυτό το αρχείο.

Αν το `config.js` μείνει κενό, η εφαρμογή δουλεύει κανονικά τοπικά.

### 3. Κλείσιμο της εγγραφής — ΕΚΚΡΕΜΕΙ

Οι λογαριασμοί δίνονται **μόνο με πρόσκληση**. Στο dashboard:

- **Authentication → Sign In / Providers → Email**: απενεργοποιήστε το
  *Allow new users to sign up*.
- **Authentication → Users → Invite user**: στέλνει πρόσκληση με email.
- **Authentication → URL Configuration → Site URL**: η διεύθυνση των Pages.
  Χωρίς αυτό οι σύνδεσμοι πρόσκλησης και επαναφοράς οδηγούν σε
  `localhost:3000` και δεν ανοίγουν ποτέ την εφαρμογή.

### Ηλεκτρονικό ταχυδρομείο — απαραίτητο πριν από πολλούς χρήστες

Η ενσωματωμένη υπηρεσία του Supabase στέλνει **ελάχιστα μηνύματα την ώρα** και
προορίζεται μόνο για δοκιμές. Με λίγες προσκλήσεις εξαντλείται και εμφανίζεται
`email rate limit exceeded`.

Πριν δοθεί πρόσβαση σε συναδέλφους, ρυθμίστε δικό σας SMTP:
**Project Settings → Authentication → SMTP Settings**. Ο διακομιστής της
υπηρεσίας ή οποιοσδήποτε πάροχος αρκεί.

Αν χρειαστεί να ξεμπλοκάρετε κάποιον χωρίς email, ο κωδικός ορίζεται
απευθείας στη βάση από το SQL Editor:

```sql
update auth.users
   set encrypted_password = extensions.crypt('<προσωρινός κωδικός>',
                                             extensions.gen_salt('bf', 10)),
       updated_at = now()
 where email = '<το email>';
```

Ο χρήστης τον αλλάζει αμέσως από το «Αλλαγή κωδικού» μέσα στην εφαρμογή.

**Αυτό δεν γίνεται από τον κώδικα και δεν έχει γίνει ακόμη.** Μέχρι να
απενεργοποιηθεί η ελεύθερη εγγραφή, οποιοσδήποτε γνωρίζει τη διεύθυνση
μπορεί να δημιουργήσει λογαριασμό.

### 4. Ανάγνωση σαρωμένων εγγράφων — ΕΚΚΡΕΜΕΙ

Για να διαβάζει η εφαρμογή φωτογραφίες και σαρωμένα, ορίστε το κλειδί του
Anthropic API ως μυστικό του Edge Function:

**Edge Functions → ocr-pinaka → Secrets** (ή *Project Settings → Edge
Functions → Secrets*), όνομα `ANTHROPIC_API_KEY`.

Μέχρι να οριστεί, η ανάγνωση σαρωμένων επιστρέφει καθαρό μήνυμα και δεν
επηρεάζει τίποτε άλλο· τα ψηφιακά PDF διαβάζονται όπως πάντα τοπικά.

### 5. Δημοσίευση

Το repo δημοσιεύεται ως GitHub Pages μέσω του `.github/workflows/pages.yml`.
Ενεργοποιήστε το από **Settings → Pages → Source: GitHub Actions**.

Στο **Authentication → URL Configuration** του Supabase προσθέστε τη
διεύθυνση των Pages στα *Redirect URLs*, ώστε να δουλεύει η επαναφορά κωδικού.

## Μοντέλο πρόσβασης

- Η εγγραφή γίνεται μόνο με πρόσκληση.
- Κάθε συνδεδεμένος χρήστης **διαβάζει** όλα τα έργα.
- **Γράφει** μόνο στα δικά του — κανείς δεν σβήνει κατά λάθος ξένη δουλειά.
- Κάθε αποθήκευση κρατά την προηγούμενη κατάσταση στον πίνακα
  `project_revisions`: ποιος άλλαξε τι και πότε.
- Δύο χρήστες στο ίδιο έργο: αισιόδοξο κλείδωμα. Αν η έκδοση στη βάση έχει
  προχωρήσει, η εγγραφή **δεν** περνά και ο χρήστης ειδοποιείται.

## Εργασία χωρίς σύνδεση

Η τοπική αποθήκευση του φυλλομετρητή είναι η κύρια πηγή. Ο συγχρονισμός
είναι επιπλέον στρώμα. Μηχανικός σε εργοτάξιο χωρίς σήμα συνεχίζει να
δουλεύει· τα έργα ανεβαίνουν μόλις επανέλθει η σύνδεση.

## Προστασία δεδομένων

Η εφαρμογή συγκεντρώνει **Α.Φ.Μ. αναδόχων και ονόματα υπαλλήλων**. Ακόμη κι
αν τα έγγραφα-πηγή είναι δημόσια, η συγκέντρωσή τους σε αναζητήσιμη βάση
είναι χωριστό ζήτημα. Συζητήστε το με τον υπεύθυνο προστασίας δεδομένων του
φορέα πριν καταχωριστούν πραγματικά έργα.

## Έλεγχος

```
python3 tools/check_syntax.py      # συντακτικός έλεγχος κάθε script block
node tools/smoke.mjs               # εκτέλεση σε πραγματικό Chromium
```

Το `tools/smoke.mjs` χρειάζεται `npm i -D playwright`.

Οι πολιτικές ασφαλείας ελέγχονται με το `tools/rls_test.sql`: εκτελέστε το
στο SQL Editor του Supabase. Δημιουργεί δύο πλασματικούς χρήστες, δοκιμάζει
κάθε πολιτική και τα σβήνει στο τέλος. Κάθε γραμμή πρέπει να λέει `OK`.

Ο κύκλος σύνδεσης και συγχρονισμού ελέγχεται χωρίς πραγματική βάση:

```
node tools/mock/supabase-mock.mjs      # σε ένα τερματικό
node tools/sync_test.mjs               # σε άλλο
node tools/invite_test.mjs             # πρόσκληση και ορισμός κωδικού
node tools/ocr_test.mjs                # ανάγνωση σαρωμένων και φωτογραφιών
```

Το `tools/ocr_test.mjs` ελέγχει τον πελάτη, όχι το μοντέλο: ότι ζητείται
συγκατάθεση πριν φύγει το αρχείο, ότι η άρνηση δεν αφήνει μισοτελειωμένη
κατάσταση, ότι κάθε γραμμή επαληθεύεται αριθμητικά, και ότι οι αβέβαιες
γραμμές μένουν σημασμένες μέχρι να ελεγχθούν.

## Σαρωμένα έγγραφα και φωτογραφίες

Ο τοπικός αναγνώστης βγάζει κείμενο μόνο από PDF που το περιέχουν. Σε
σαρωμένο ή φωτογραφημένο έγγραφο δεν υπάρχει κείμενο.

Η κλασική OCR δεν είναι επαρκής εδώ, και αυτό μετρήθηκε αντί να υποτεθεί:
πάνω σε **καθαρή απόδοση** προϋπολογισμού η Tesseract στα ελληνικά έβγαλε
**7 από 21 αριθμούς σωστά** και **0 από 7 κωδικούς αναθεώρησης** — το
«241,00 5,00 1.205,00» έγινε «9806 ἀθδ 2665». Λάθος ποσά σε έγγραφο που πάει
σε Τεχνικό Συμβούλιο είναι απαράδεκτα, και μια OCR που σφάλλει *σιωπηλά*
είναι χειρότερη από καμία. Γι' αυτό η ανάγνωση γίνεται από μοντέλο που
καταλαβαίνει δομή πίνακα, στο Edge Function `ocr-pinaka`.

Τρία πράγματα δεν διαπραγματεύονται:

1. **Συγκατάθεση κάθε φορά.** Το αρχείο δεν φεύγει από τον υπολογιστή χωρίς
   ρητό «ναι» για το συγκεκριμένο αρχείο.
2. **Ανεξάρτητη αριθμητική επαλήθευση.** Η υπηρεσία επιστρέφει και τη
   *δαπάνη όπως γράφεται στο χαρτί*, χωρίς να την υπολογίσει. Η εφαρμογή
   ελέγχει `ποσότητα × τιμή` έναντι αυτής σε κάθε γραμμή, και το άθροισμα
   έναντι του «Αθροίσματος» του εγγράφου. Κάθε απόκλιση αναφέρεται ρητά.
3. **Ορατή αβεβαιότητα.** Όποια γραμμή δεν διαβάστηκε με βεβαιότητα μένει
   σημασμένη με ⚠ στο βήμα 2 μέχρι να την ελέγξει ο χρήστης. Η ανάγνωση από
   εικόνα **δεν εμφανίζεται ποτέ ως πράσινο μήνυμα**, ούτε όταν όλα κλείνουν.

Τα διοικητικά έγγραφα (αποφάσεις, συμβάσεις, πρωτόκολλα) περνούν από τον ίδιο
δρόμο σε λειτουργία απλής μεταγραφής: το κείμενο επιστρέφει στην εφαρμογή και
το διαβάζουν οι **ίδιοι** αναγνώστες που δουλεύουν ήδη πάνω σε ψηφιακά PDF —
δεν υπάρχουν δύο διαφορετικές λογικές εξαγωγής.

Δέχονται εικόνα όλα τα σημεία εισαγωγής: προϋπολογισμός, οικονομική προσφορά,
μεμονωμένο έγγραφο, μαζική εισαγωγή και έλεγχος Πίνακα τρίτου.

## Πώς μπαίνει ένας νέος χρήστης

Το «Invite user» **δεν δημιουργεί κωδικό**. Στέλνει σύνδεσμο που περιέχει
έτοιμη συνεδρία στο fragment της διεύθυνσης:

```
https://…/index.html#access_token=…&type=invite
```

Η εφαρμογή διαβάζει το fragment, το καθαρίζει από τη διεύθυνση ώστε να μη
μείνει το token στο ιστορικό, και ζητά από τον χρήστη να ορίσει κωδικό. Από
εκεί και πέρα συνδέεται κανονικά με email και κωδικό.

Ο ίδιος μηχανισμός εξυπηρετεί και το «Ξέχασα τον κωδικό», και το «Αλλαγή
κωδικού» για ήδη συνδεδεμένο χρήστη.
